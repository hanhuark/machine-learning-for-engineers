# Adoption guide

## Use one module

1. Choose a module whose prerequisites match the host course.
2. Read its README, assignment, tutorial, data source, and license conditions.
3. Run the tutorial locally in a clean environment before assigning it.
4. Adapt the engineering context and assessment criteria, but retain data provenance, units, split rules, and limitations.
5. Provide your own held-out evaluation material if the work will be graded.

## Use several modules

Start with regression and classification before vision or an advanced-track module. Pair each new method with one explicit engineering decision, a baseline, an independent test, and a failure-analysis requirement. Use [COURSE_MAP.md](COURSE_MAP.md) for the recommended progression.

## Adapt responsibly

- Keep the BSD 3-Clause license and original attribution when redistributing derived material.
- Check rights and citation requirements for every external dataset, image, notebook, and model weight.
- Do not represent synthetic demonstrations as experimental validation.
- Do not copy current answer keys, instructor-held tests, student records, or confidential research data into public forks.

## Report improvements

Please open an issue or pull request for corrected links, clearer explanations, reproducibility repairs, accessibility improvements, new mechanics-focused examples, or instructor adaptation notes. See [CONTRIBUTING.md](CONTRIBUTING.md).

If you publicly implement one or more modules, you may also request inclusion in the [implementations record](IMPLEMENTATIONS.md). Inclusion requires an instructor-approved, publicly shareable description; it is not an evaluation of educational impact.
