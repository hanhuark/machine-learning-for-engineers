# Contributing

Contributions should improve engineering learning, reproducibility, accessibility, or maintenance without exposing restricted or student information.

## Before opening an issue or pull request

1. Identify the module, file, and exact problem or opportunity.
2. State whether the concern is instructional, technical, data-related, accessibility-related, or a broken link.
3. For code changes, provide a minimal reproducible command and its observed result.
4. For data/materials, confirm that you have redistribution permission and provide provenance, units, and license information.
5. Do not submit student records, private grading materials, confidential research data, credentials, or unreleased intellectual property.

## Pull-request expectations

- Keep changes scoped and explain their educational rationale.
- Preserve units, assumptions, data provenance, citations, and current module boundaries.
- Add or update tests when code behavior changes.
- Run the relevant tutorial/test command and report what was verified.
- Avoid replacing a student learning task with an opaque finished solution.

## Content principles

Teaching material should state the engineering question, variables and units, baseline, evaluation method, limitations, and at least one likely failure mode. Where AI tools are relevant, require students to audit outputs and demonstrate individual understanding.
