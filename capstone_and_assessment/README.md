# Capstone and assessment

The final evidence of engineering learning is not an uploaded notebook or
report alone. Students should demonstrate that they can defend the problem
formulation, interpret a result, identify a limitation, and respond to a
changed condition.

Use the repository-wide [assessment policy](../teaching_resources/ASSESSMENT_AND_AI_POLICY.md),
[engineering ML rubric](../teaching_resources/ENGINEERING_ML_RUBRIC.md), and
[quiz readiness guide](../teaching_resources/QUIZ_READINESS_GUIDE.md).

## Standard capstone checkpoints

1. Engineering problem, decision owner, system boundary, variables, units, and
   data/rights plan.
2. Baseline, split/evaluation plan, expected failure modes, and AI-use boundary.
3. Working analysis or prototype with reproducibility record and interim error
   audit.
4. Held-out evaluation, physical plausibility check, limitation statement, and
   communication artifact.
5. Individual defense, live modification, or bounded physical demonstration.

AI may be permitted in any checkpoint only under an explicit assignment mode.
The assessment focuses on the student’s engineering judgment and verification,
not authorship detection.
