# Instructor guide

## Intended use

This repository supports a full technical elective, selected modules within an existing course, or guided project work. It is not a turnkey replacement for institutional policies, local accessibility requirements, or instructor judgment.

## Before the term

1. Select modules, define their dates, and identify the current assignment specifications.
2. Confirm software, student hardware, cloud/HPC access, data licenses, and accessibility accommodations.
3. Make a private instructor area for answer keys, grading notes, current rubrics, and instructor-held evaluation data.
4. Publish the AI-use policy and explain which activities are AI-free, AI-assisted, or AI-audited.
5. Run each assigned tutorial in a clean supported environment; record the command, version, expected runtime, and known limitations.

## Suggested assessment mix

| Evidence | Suggested share | Purpose |
| --- | ---: | --- |
| Supervised foundational checks | 15-20% | Verify indispensable concepts and code reading |
| Module assignments | 40-50% | Develop reproducible technical practice |
| Individual verification | 10-15% | Confirm personal understanding and modification ability |
| Project, presentation, and peer review | 20-30% | Apply methods to an authentic engineering question |

Use the [shared rubric](teaching_resources/ENGINEERING_ML_RUBRIC.md) unless a module requires more specific criteria.

## AI-era assessment design

Students should learn to use coding agents as junior collaborators: formulate a testable request, inspect assumptions, run the code, identify errors, and decide whether results support an engineering claim. Do not make a model-generated notebook the primary evidence of individual learning.

For each major assignment, use at least one of the following:

- an instructor-held data set or altered operating condition released after the initial submission;
- a five-minute individual explanation or live modification;
- a required error/failure audit;
- staged submissions showing the split strategy and baseline before final modeling;
- a critique of an AI-generated suggestion using independent evidence.

## Student privacy and public work

Only publish student projects or identifiable artifacts with documented permission. Keep grades, student records, private data, answer keys, and unreleased research outside this public repository.

## Continuous improvement

At the end of each offering, record: student feedback, completion/withdrawal patterns, common conceptual errors, tutorial failures, accessibility issues, AI-policy friction, and project outcomes. Make changes on a branch, tag the course version by term, and preserve prior assignment versions for auditability.
